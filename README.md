# Telegram Business AutoReply для Premium / ZimaOS

Автоответчик для **личного Telegram Premium/Business-аккаунта**, работающий через официальный Telegram Bot API и Business Connection. Бот отвечает **от имени вашего аккаунта**, а не отдельным чатом бота.

## Что умеет

- автоответ пользователю при первом увиденном сообщении;
- повторный автоответ, если пользователь не писал заданное количество часов (по умолчанию 168 часов / 7 дней);
- inline-кнопки в сообщении и отдельный ответ при нажатии;
- админ-панель внутри Telegram;
- добавление, редактирование, включение/выключение и удаление кнопок;
- настройка приветствия, интервала и количества кнопок в строке;
- SQLite с сохранением между перезапусками контейнера;
- базовая статистика;
- Docker Compose, подходящий для ZimaOS.

## Стартовые кнопки

1. Написать пользователю
2. Заказать мероприятие
3. Аренда оборудования
4. Аренда Фабрики
5. Другое

Все названия и ответы можно менять из `/admin`.

## Почему не Telethon

Для Telegram Premium есть официальный путь: Telegram Business позволяет подключить обычного бота к личному аккаунту и разрешить ему обрабатывать входящие сообщения и отвечать от имени владельца. Поэтому проекту нужен только `BOT_TOKEN`, без `api_id`, `api_hash`, номера телефона и user-session.

## 1. Создать бота

1. Откройте `@BotFather`.
2. Создайте бота через `/newbot` и получите токен.
3. В настройках бота включите **Business Mode / Secretary Mode** (название может зависеть от версии Telegram).

Проверка: при запуске в логах должно быть `can_connect_to_business=True`.

## 2. Подключить бота к Premium-аккаунту

В Telegram на вашем Premium-аккаунте откройте:

`Настройки -> Telegram Business -> Чат-боты / Chatbots`

Подключите созданного бота и дайте ему как минимум право отвечать на сообщения (`can_reply`). Можно ограничить доступ, например только новыми чатами или не-контактами.

Важно: Telegram разрешает Business-боту отвечать в подходящих приватных чатах после входящего сообщения; право `can_reply` относится к чатам с недавней входящей активностью.

## 3. Настроить `.env`

Скопируйте пример:

```bash
cp .env.example .env
```

Заполните:

```env
BOT_TOKEN=123456789:ВАШ_ТОКЕН
ADMIN_IDS=123456789
DATABASE_PATH=/data/bot.db
LOG_LEVEL=INFO
```

`ADMIN_IDS` — Telegram user ID владельца/администраторов. Можно несколько через запятую:

```env
ADMIN_IDS=123456789,987654321
```

## 4. Запуск Docker

```bash
docker compose up -d --build
```

Логи:

```bash
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

База лежит в `./data/bot.db` и не пропадает после пересоздания контейнера.

## ZimaOS

Проект можно запустить как обычный Docker Compose stack. Создайте папку приложения, положите туда файлы проекта и `.env`, затем импортируйте `docker-compose.yml` через интерфейс ZimaOS или запустите Compose из терминала.

Порт наружу не нужен: бот использует long polling и сам подключается к Telegram.

## Админ-панель

1. Напишите вашему боту `/start` или `/admin` с аккаунта, чей ID есть в `ADMIN_IDS`.
2. В панели доступны:
   - приветствие;
   - интервал повторного автоответа;
   - сетка кнопок 1–3 в строке;
   - конструктор кнопок;
   - конструктор пошаговых форм и вопросов;
   - привязка форм к кнопкам;
   - включение/выключение автоответчика;
   - статистика, включая количество отправленных заявок.

## Пошаговые формы заявок

В версии 1.3 кнопки могут запускать пошаговые анкеты. По умолчанию формы автоматически создаются и привязываются к кнопкам «Заказать мероприятие», «Аренда оборудования», «Аренда Фабрики» и «Другое». «Написать пользователю» остаётся обычным текстовым действием.

Во время заполнения ответы и текущий шаг сохраняются в SQLite. Пользователь может вернуться назад, пропустить необязательный вопрос или отменить заявку. После последнего вопроса бот показывает сводку; только после нажатия «Отправить заявку» создаётся запись и каждому ID из `ADMIN_IDS` приходит отдельное сообщение с данными клиента и всеми ответами.

В `/admin` появился раздел **📝 Формы**: создание и удаление форм, редактирование названия, вопросов, порядка и обязательности, включение/выключение и привязка формы к одной или нескольким кнопкам. У одной кнопки одновременно может быть только одна форма.

## Логика автоответа

На каждое входящее сообщение сохраняется время последнего контакта. Ответ отправляется, если:

- этот `chat_id` ещё не был замечен базой; или
- с предыдущего входящего сообщения прошло не меньше `cooldown_hours`.

Пример: при 168 часах пользователь написал сегодня — автоответ сработает один раз. Если он продолжит писать через минуту/час/день, повторного приветствия не будет. Если снова напишет через 7+ дней, приветствие появится снова.

### Первый запуск и старые чаты

Бот не импортирует всю старую историю личного Telegram. Поэтому первый входящий апдейт от уже существующего собеседника будет считаться первым увиденным сообщением для локальной базы. Дальше история ведётся корректно в SQLite.

## Ограничение Telegram Business

Telegram Business ограничивает право бота отвечать от имени аккаунта условиями Business Connection и недавней входящей активностью. Поэтому если пользователь нажмёт старую inline-кнопку спустя длительное время, Telegram может не разрешить отправить новый ответ от имени аккаунта. В таком случае ошибка будет записана в лог.

## Безопасность

- Не публикуйте `.env` и `BOT_TOKEN`.
- Ограничьте `ADMIN_IDS` только доверенными аккаунтами.
- Папку `data` включайте в резервную копию, если важна история автоответов.
- В Telegram Business можно исключить личные контакты и разрешить боту работать только с нужными категориями чатов.

## ZimaOS / CasaOS — установка без сборки

Для ZimaOS подготовлен `docker-compose.zimaos.yml`, который использует готовый multi-arch образ:

```text
ghcr.io/spacesarmat/tgautoreply:latest
```

Поддерживаемые архитектуры: `linux/amd64` и `linux/arm64`.

### Первый запуск

1. В GitHub должен существовать репозиторий `spacesarmat/telegram-business-autoreply`.
2. Загрузите в него содержимое этого проекта в ветку `main`.
3. Workflow `.github/workflows/publish-ghcr.yml` автоматически соберёт и опубликует образ в GHCR.
4. После первой публикации откройте страницу пакета GitHub Packages и убедитесь, что Container package имеет Visibility = `Public`. Это нужно, чтобы ZimaOS мог скачать образ без логина в GHCR.
5. В `docker-compose.zimaos.yml` замените:
   - `PASTE_BOT_TOKEN_HERE` — на токен от BotFather;
   - `PASTE_YOUR_TELEGRAM_USER_ID_HERE` — на Telegram user ID администратора.
6. Импортируйте YAML в ZimaOS/CasaOS и запустите приложение.

Локальная сборка на ZimaOS больше не требуется. При каждом push в `main` GitHub Actions пересобирает тег `latest`; теги вида `v1.3.0` также публикуются как отдельные версии образа.

Данные SQLite сохраняются в:

```text
/DATA/AppData/telegram-business-autoreply/data/bot.db
```

Status-страница после запуска:

```text
http://IP_ZIMAOS:18080
```

Управление ботом выполняется в Telegram командой `/admin`.

## Автоматическая публикация GHCR

Workflow использует стандартный `GITHUB_TOKEN`, поэтому отдельный Docker/GHCR пароль в GitHub Secrets не нужен. Для сборки используются Docker Buildx и QEMU, образ публикуется одновременно для AMD64 и ARM64.

Workflow запускается:

- при push в `main`;
- при создании тега `v*`;
- вручную через **Actions -> Publish GHCR image -> Run workflow**.
