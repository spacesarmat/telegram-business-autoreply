# Telegram Business AutoReply для Premium / ZimaOS

## v1.5.2 — локальный часовой пояс вместо UTC в интерфейсе

Все даты и время, которые видит пользователь или администратор, теперь отображаются в часовом поясе бизнеса из переменной `TZ`. Например, при `TZ=Europe/Moscow` timestamp `08:15 UTC` будет показан как `11:15`. UTC остаётся только внутренним форматом хранения в SQLite — это сохраняет корректную сортировку и совместимость старых данных.

Локальный часовой пояс используется для **«сегодня» в календаре, списка занятости, времени создания заявки и журнала изменений**. Telegram Bot API не передаёт часовой пояс каждого собеседника, поэтому используется единый часовой пояс бизнеса/аккаунта. Он задаётся в `.env` или Docker Compose, например `TZ=Europe/Moscow`.

## v1.5.0 — расширенная мини-CRM

В карточке заявки появились **стоимость, предоплата, остаток и внутренняя заметка администратора**. Добавлены **поиск заявок и клиентов** по номеру заявки, имени, username, телефону и содержимому формы, а также **история клиента** с предыдущими заявками и журналом последних изменений текущей заявки.

Тексты уведомлений при смене статуса теперь редактируются через `/admin → 💬 Шаблоны статусов`. В шаблонах доступны переменные `{id}`, `{form}`, `{status}`, `{client}`, `{amount}`, `{prepayment}` и `{balance}`. Существующая SQLite-база автоматически мигрирует без удаления старых заявок.

## v1.4.3 — время окончания и аренда через полночь

В форме **«Аренда Фабрики»** вместо вопроса о продолжительности теперь используется отдельное поле **«Окончание»**. Клиент выбирает время начала и время окончания, например **21:00 → 05:00**. Если окончание по часам раньше начала, бот автоматически понимает, что мероприятие заканчивается на следующий день.

Интервал `21:00–05:00` считается как **8 часов** и резервирует сразу две части календаря: `21:00–24:00` в выбранную дату и `00:00–05:00` на следующий день. Поэтому другая подтверждённая заявка не сможет занять пересекающееся время ни вечером, ни после полуночи. В выборе времени окончания варианты следующего дня отмечены `+1д`.

Для старой стандартной формы вопрос **«Продолжительность»** автоматически мигрирует в **«Окончание»**, если он не был изменён вручную. Старые уже созданные заявки с продолжительностью продолжают корректно рассчитываться. Ручная блокировка в `/admin → 📅 Занятость` также принимает ночные интервалы вида `21:00-05:00`.

## v1.4.2 — надёжный ввод телефона

В Telegram Business нативная reply-кнопка `request_contact` может не отображаться в личном диалоге с Business-аккаунтом. Поэтому поле **📱 Контакт** теперь использует ручной ввод как основной и гарантированный способ: бот показывает пример номера, проверяет, что введено **7–15 цифр**, принимает распространённые разделители (`+`, пробелы, скобки, дефисы) и сохраняет номер в нормализованном виде. Значения вроде `4`, `123` или произвольный текст больше не принимаются.

Telegram-контакт, отправленный пользователем через доступные ему средства клиента, по-прежнему принимается. Отдельное служебное сообщение «Можно отправить свой номер одной кнопкой» удалено, чтобы не вводить пользователя в заблуждение.

## v1.4.1 — уведомления клиента при смене статуса

При изменении статуса заявки в `/admin` клиент получает уведомление **в том же личном Telegram Business-чате**, где была создана заявка. Поддерживаются статусы **Новая**, **В работе**, **Подтверждена**, **Оплачена**, **Завершена** и **Отказ**. Повторное нажатие уже установленного статуса не отправляет дубликат.

Если Telegram временно не разрешает отправить Business-сообщение, сам статус и занятость всё равно сохраняются, а администратор получает предупреждение. Для заявок, созданных до появления поля `business_connection_id`, бот пытается использовать текущее активное Business-соединение.

## v1.4.0 — занятость, время и мини-CRM

В версии 1.4 добавлен календарь занятости и управление заявками. Поле **📅 Дата** показывает полностью занятые дни (`×`) и дни с частично занятым временем (`•`). Новый тип вопроса **🕐 Время** выводит доступные интервалы кнопками; занятые интервалы нельзя выбрать. Для стандартной формы «Аренда Фабрики» существующий вопрос «Время» автоматически мигрирует на новый тип.

В `/admin` появились разделы **📋 Заявки** и **📅 Занятость**. Заявки имеют статусы: Новая → В работе → Подтверждена → Оплачена → Завершена / Отказ. При переводе заявки в «Подтверждена», «Оплачена» или «Завершена» её дата и время автоматически блокируются. Если другая заявка пересекается с уже занятым интервалом, подтвердить её нельзя. Ручные блокировки поддерживают весь день или интервал вида `18:00-23:00`.

Существующая SQLite-база мигрирует автоматически: старые заявки, формы, кнопки и настройки сохраняются.


## v1.3.4 — календарь и отправка своего контакта

В конструктор форм добавлены типы полей **Текст / Дата / Контакт**. Для поля «Дата» пользователь получает inline-календарь с переключением месяцев и кнопкой «Сегодня», при этом ручной ввод `ДД.ММ.ГГГГ` остаётся доступен. Для поля «Контакт» Telegram показывает кнопку **📱 Поделиться своим контактом**; номер также можно ввести вручную. Тип поля меняется через `/admin` → **📝 Формы** → вопрос → **Тип**.

После подтверждения формы итоговая карточка заявки остаётся прямо в текущем Telegram Business-диалоге с клиентом. Заявка также сохраняется в SQLite.

Автоответчик для **личного Telegram Premium/Business-аккаунта**, работающий через официальный Telegram Bot API и Business Connection. Бот отвечает **от имени вашего аккаунта**, а не отдельным чатом бота.

## Что умеет

- автоответ пользователю при первом увиденном сообщении;
- повторный автоответ, если пользователь не писал заданное количество часов (по умолчанию 168 часов / 7 дней);
- inline-кнопки в сообщении и отдельный ответ при нажатии;
- админ-панель внутри Telegram;
- добавление, редактирование, включение/выключение и удаление кнопок;
- настройка приветствия, интервала, количества кнопок в строке и фраз ручного вызова меню;
- SQLite с сохранением между перезапусками контейнера;
- базовая статистика;
- Docker Compose, подходящий для ZimaOS.

## Почему не Telethon

Для Telegram Premium есть официальный путь: Telegram Business позволяет подключить обычного бота к личному аккаунту и разрешить ему обрабатывать входящие сообщения и отвечать от имени владельца. Поэтому проекту нужен только `BOT_TOKEN`, без `api_id`, `api_hash`, номера телефона и user-session.

## 1. Создать бота

1. Откройте `@BotFather`.
2. Создайте бота через `/newbot` и получите токен.
3. В настройках бота включите **Business Mode / Secretary Mode** (название может зависеть от версии Telegram).

Проверка: при запуске в логах должно быть `can_connect_to_business=True`.

## 2. Подключить бота к Premium-аккаунту

В Telegram на вашем Premium-аккаунте откройте:

`Настройки -> Telegram Business -> Чат-боты / Chatbots`

Подключите созданного бота и дайте ему как минимум право отвечать на сообщения (`can_reply`). Для «чистых» форм, где ответы пользователя удаляются после сохранения, дополнительно включите **Удаление входящих**. Можно ограничить доступ, например только новыми чатами или не-контактами.

Важно: Telegram разрешает Business-боту отвечать в подходящих приватных чатах после входящего сообщения; право `can_reply` относится к чатам с недавней входящей активностью.

## 3. Настроить `.env`

Скопируйте пример:

```bash
cp .env.example .env
```

Заполните:

```env
BOT_TOKEN=123456789:ВАШ_ТОКЕН
ADMIN_IDS=123456789
DATABASE_PATH=/data/bot.db
LOG_LEVEL=INFO
TZ=Europe/Moscow
```

`ADMIN_IDS` — Telegram user ID владельца/администраторов. Можно несколько через запятую:

```env
ADMIN_IDS=123456789,987654321
```

### Часовой пояс

`TZ` задаёт локальное время бизнеса в формате IANA, например `Europe/Moscow`, `Europe/Berlin` или `Asia/Dubai`. Служебные timestamps хранятся в UTC, но в Telegram отображаются в указанной зоне. Telegram Bot API не сообщает часовой пояс каждого клиента автоматически.

## 4. Запуск Docker

```bash
docker compose up -d --build
```

Логи:

```bash
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

База лежит в `./data/bot.db` и не пропадает после пересоздания контейнера.

## ZimaOS

Проект можно запустить как обычный Docker Compose stack. Создайте папку приложения, положите туда файлы проекта и `.env`, затем импортируйте `docker-compose.yml` через интерфейс ZimaOS или запустите Compose из терминала.

Порт наружу не нужен: бот использует long polling и сам подключается к Telegram.

## Админ-панель

1. Напишите вашему боту `/start` или `/admin` с аккаунта, чей ID есть в `ADMIN_IDS`.
2. В панели доступны:
   - приветствие;
   - интервал повторного автоответа;
   - сетка кнопок 1–3 в строке;
   - конструктор кнопок;
   - конструктор пошаговых форм и вопросов;
   - редактор фраз ручного вызова меню (`/menu`, `меню`, `заявка` по умолчанию);
   - привязка форм к кнопкам;
   - включение/выключение автоответчика;
   - статистика, включая количество отправленных заявок.

## Пошаговые формы заявок

В версии 1.3 кнопки могут запускать пошаговые анкеты. По умолчанию формы автоматически создаются и привязываются к кнопкам «Заказать мероприятие», «Аренда оборудования», «Аренда Фабрики» и «Другое». «Написать пользователю» остаётся обычным текстовым действием.

Во время заполнения ответы и текущий шаг сохраняются в SQLite. Пользователь может вернуться назад, пропустить необязательный вопрос или отменить заявку. После последнего вопроса бот показывает сводку; после нажатия «Отправить заявку» итоговая карточка остаётся в том же личном Business-чате, а запись сохраняется в SQLite.

В `/admin` есть раздел **📝 Формы**: создание и удаление форм, редактирование названия, вопросов, порядка, обязательности и **типа поля**, включение/выключение и привязка формы к одной или нескольким кнопкам. Доступные типы вопроса: **⌨️ Текст**, **📅 Дата**, **🕐 Время**, **📱 Контакт**. У одной кнопки одновременно может быть только одна форма.

## Ручной вызов главного меню

Начиная с версии 1.3.2 пользователь может вызвать меню прямо в личной переписке с вашим Business-аккаунтом, даже если обычный автоответ уже сработал недавно и cooldown ещё не истёк. По умолчанию распознаются фразы:

```text
/menu
меню
заявка
```

Регистр не важен: `Меню`, `МЕНЮ` и `меню` работают одинаково. Команда вида `/menu@BotUsername` также распознаётся как `/menu`.

Если пользователь вызывает меню во время заполнения формы, текущая незавершённая сессия закрывается и то же сообщение формы превращается в главное меню. В каждой форме также есть кнопка **🏠 Главное меню**.

Список фраз меняется через `/admin` → **⚡ Вызов меню**. Можно указать до 20 фраз, по одной в строке. Ручной вызов меню не зависит от интервала повторного автоответа.

## Логика автоответа

На каждое входящее сообщение сохраняется время последнего контакта. Ответ отправляется, если:

- этот `chat_id` ещё не был замечен базой; или
- с предыдущего входящего сообщения прошло не меньше `cooldown_hours`.

Пример: при 168 часах пользователь написал сегодня — автоответ сработает один раз. Если он продолжит писать через минуту/час/день, повторного приветствия не будет. Если снова напишет через 7+ дней, приветствие появится снова.

### Первый запуск и старые чаты

Бот не импортирует всю старую историю личного Telegram. Поэтому первый входящий апдейт от уже существующего собеседника будет считаться первым увиденным сообщением для локальной базы. Дальше история ведётся корректно в SQLite.

## Ограничение Telegram Business

Telegram Business ограничивает право бота отвечать от имени аккаунта условиями Business Connection и недавней входящей активностью. Поэтому если пользователь нажмёт старую inline-кнопку спустя длительное время, Telegram может не разрешить отправить новый ответ от имени аккаунта. В таком случае ошибка будет записана в лог.

## Безопасность

- Не публикуйте `.env` и `BOT_TOKEN`.
- Ограничьте `ADMIN_IDS` только доверенными аккаунтами.
- Папку `data` включайте в резервную копию, если важна история автоответов.
- В Telegram Business можно исключить личные контакты и разрешить боту работать только с нужными категориями чатов.

## ZimaOS / CasaOS — установка без сборки

Для ZimaOS подготовлен `docker-compose.zimaos.yml`, который использует готовый multi-arch образ:

```text
ghcr.io/spacesarmat/tgautoreply:latest
```

Поддерживаемые архитектуры: `linux/amd64` и `linux/arm64`.

### Первый запуск

1. В GitHub должен существовать репозиторий `spacesarmat/telegram-business-autoreply`.
2. Загрузите в него содержимое этого проекта в ветку `main`.
3. Workflow `.github/workflows/publish-ghcr.yml` автоматически соберёт и опубликует образ в GHCR.
4. После первой публикации откройте страницу пакета GitHub Packages и убедитесь, что Container package имеет Visibility = `Public`. Это нужно, чтобы ZimaOS мог скачать образ без логина в GHCR.
5. В `docker-compose.zimaos.yml` замените:
   - `PASTE_BOT_TOKEN_HERE` — на токен от BotFather;
   - `PASTE_YOUR_TELEGRAM_USER_ID_HERE` — на Telegram user ID администратора.
6. Импортируйте YAML в ZimaOS/CasaOS и запустите приложение.

Локальная сборка на ZimaOS больше не требуется. При каждом push в `main` GitHub Actions пересобирает тег `latest`; теги вида `v1.5.2` также публикуются как отдельные версии образа.

Данные SQLite сохраняются в:

```text
/DATA/AppData/telegram-business-autoreply/data/bot.db
```

Status-страница после запуска:

```text
http://IP_ZIMAOS:18080
```

Управление ботом выполняется в Telegram командой `/admin`.

## Автоматическая публикация GHCR

Workflow использует стандартный `GITHUB_TOKEN`, поэтому отдельный Docker/GHCR пароль в GitHub Secrets не нужен. Для сборки используются Docker Buildx и QEMU, образ публикуется одновременно для AMD64 и ARM64.

Workflow запускается:

- при push в `main`;
- при создании тега `v*`;
- вручную через **Actions -> Publish GHCR image -> Run workflow**.
