# v1.9.0 — календарь, напоминания и резервные копии

Релиз усиливает эксплуатационную часть Telegram Business AutoReply: Web Admin теперь показывает полноценный календарь бронирований, бот умеет автоматически напоминать о подтверждённых мероприятиях, а SQLite ежедневно резервируется с возможностью скачать и восстановить копию из браузера.

## Добавлено

### 🗓 Календарь Web Admin

- новый раздел `/admin/calendar`;
- помесячный просмотр с переходом между месяцами;
- отдельное отображение фактической аренды;
- отдельные интервалы технического буфера до/после — монтаж и уборка;
- ручные блокировки занятости;
- переход из события календаря прямо в карточку заявки.

### 🔔 Напоминания

- отдельный раздел Web Admin `Напоминания`;
- интервалы для клиента и администратора настраиваются независимо, например `168,24,3` часа;
- редактируемые шаблоны сообщений;
- переменные `{id}`, `{form}`, `{client}`, `{username}`, `{date}`, `{time}`, `{hours_before}`, `{amount}`, `{prepayment}`, `{balance}`;
- напоминания создаются только для заявок со статусом `Подтверждена` или `Оплачена`;
- защита от повторной отправки одного и того же напоминания;
- повторные попытки после временной ошибки Telegram;
- ограниченное окно опоздания, чтобы после долгого простоя не отправлять давно неактуальные напоминания;
- история отправок и ошибок в Web Admin.

Клиентские напоминания отправляются через сохранённый Telegram Business Connection. Если Telegram не разрешает проактивную отправку в конкретный диалог из-за ограничений Business reply window, заявка не меняется: ошибка записывается в историю, а напоминание администратору продолжает работать.

По умолчанию напоминания выключены: после обновления администратор сам включает их в Web Admin.

### 💾 SQLite backups

- ежедневный автоматический backup базы через официальный SQLite backup API;
- резервные копии хранятся в `/data/backups` по умолчанию;
- настройка локального часа создания через Web Admin;
- настройка количества хранимых копий (по умолчанию 30);
- ручное создание backup;
- скачивание backup из Web Admin;
- восстановление выбранной копии;
- перед восстановлением автоматически создаётся страховочная `pre-restore` копия текущей базы;
- `PRAGMA integrity_check` до/после восстановления;
- эксклюзивный maintenance gate на время восстановления: новые DB-операции кратковременно ждут, активные завершаются штатно.

Автобэкапы включены по умолчанию и создаются один раз в сутки после `04:00` по часовому поясу `TZ`.

## Docker / ZimaOS

Добавлена необязательная переменная:

```env
BACKUP_DIR=/data/backups
```

Каталог `/data` уже находится в постоянном bind mount, поэтому резервные копии переживают пересоздание контейнера.

## Совместимость

- существующая SQLite-база мигрирует автоматически;
- старые заявки, формы, тарифы, Web Admin и Telegram `/admin` сохраняются;
- новая таблица истории напоминаний создаётся автоматически;
- `MAX_CONCURRENT_UPDATES` и per-chat очередь v1.8.2 продолжают работать без изменений.
