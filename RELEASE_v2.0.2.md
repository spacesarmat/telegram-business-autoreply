# v2.0.2 — исправление выбора времени окончания

Исправление для сценария бронирования, где после выбора даты и времени начала все варианты окончания могли выглядеть занятыми.

### Что изменено

- Для каждого времени окончания вычисляется реальная причина недоступности.
- `×` может означать правило минимальной длительности, минимальный срок до события, рабочие часы, регулярную занятость, технический буфер или существующую бронь — при нажатии бот показывает конкретную причину.
- Если для выбранного времени начала нет ни одного допустимого окончания, бот не переводит клиента на следующий шаг, а сразу просит выбрать другое начало/дату.
- Исправлена проверка повторяющейся занятости по понедельникам (`weekday=0`).
- База данных не меняется; миграция не нужна.

### Обновление ZimaOS

```bash
sudo docker pull ghcr.io/spacesarmat/tgautoreply:latest
```

После pull пересоздайте контейнер. Каталог `/DATA/AppData/telegram-business-autoreply/data` сохраняется.
