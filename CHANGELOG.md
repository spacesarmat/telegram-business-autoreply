# Changelog

## [2.0.3] — 2026-09-20

### Добавлено

- У каждого тарифа появилось редактируемое **описание базовой стоимости** до 1500 символов.
- Описание можно менять в Telegram `/admin → 💰 Тарифы → форма → 📝 Описание базы`.
- То же поле доступно в Web Admin на странице тарифа.
- Пояснение отображается клиенту в предварительном расчёте и в итоговой карточке заявки, например что входит в 60 000 ₽.

### Исправлено

- Исправлено отображение динамических надбавок в тексте расчёта стоимости: локальные данные надбавок теперь извлекаются из расчёта перед рендерингом.

### Совместимость

- SQLite мигрируется автоматически: в `form_pricing` добавляется поле `base_description`, старые тарифы получают пустое описание.
- Существующие суммы, заявки, услуги и настройки не меняются.


## [2.0.2] — 2026-09-20

- исправлен экран выбора времени окончания: `×` больше не означает только «занято», бот знает точную причину блокировки;
- если у выбранного старта нет ни одного допустимого окончания, выбор старта отклоняется до перехода на следующий шаг;
- причины учитывают правила бронирования, регулярную занятость, технические буферы и реальные брони;
- исправлена регулярная занятость для понедельника (`weekday=0`);
- схема SQLite не менялась.


Все значимые изменения Telegram Business AutoReply.

## [2.0.1] — 2026-09-20

### Добавлено

- Системная Telegram Menu Button в личном чате с ботом; команда `/menu` открывает клиентское меню в тестовом режиме администратора.
- Inline-кнопка `☰ Меню` под обычными Business-ответами и итоговой карточкой заявки, чтобы клиент мог снова открыть меню.
- Тестовый режим администратора в ЛС с ботом: `/test` или `/admin → 🧪 Тест бота`.
- В тестовом режиме используются реальные формы, календарь, занятость, тарифы и услуги, но реальная заявка в CRM не создаётся и клики не попадают в клиентскую статистику.

### Исправлено

- Нельзя выбрать дату раньше текущей даты бизнеса (`TZ`) ни кнопкой календаря, ни ручным вводом.
- Прошедшие дни визуально отключены в календаре, переход к прошлым месяцам заблокирован.
- Повторная проверка даты выполняется непосредственно перед отправкой заявки, поэтому ограничение нельзя обойти старой inline-кнопкой или ранее начатой формой.

### Совместимость

- Схема SQLite не меняется; база v2.0.0 используется без миграции.
- Telegram Business `/menu`, Web Admin и все функции v2.0.0 сохраняются.

## [2.0.0] — 2026-09-20

### Добавлено

- Правила бронирования по форме: минимальная длительность, минимальный срок до события, горизонт брони, закрытые дни недели и рабочие часы по дням.
- Повторяющаяся занятость по дням недели с интервалом или блокировкой на весь день.
- Динамические надбавки по диапазону гостей, дню недели и ночному времени.
- Новый тип вопроса `📎 Файл / фото` с сохранением вложений в постоянный `/data/uploads` и просмотром из Web Admin.
- Отдельный раздел `Клиенты` в Web CRM: история заявок, суммы и внутренние заметки.
- Роли Web Admin `owner`, `manager`, `viewer` через `WEB_ADMIN_USERS`.
- Общий журнал аудита Web Admin и изменений заявок из Telegram.
- Аналитика: заявки, успешные брони, отмены, сумма подтверждённых/оплаченных/завершённых заявок, средний чек, конверсия, формы и месяцы.
- Экспорт всех заявок в CSV и Excel (`.xlsx`).
- Клиентский экран `Моя заявка` и запросы на изменение брони, услуг или отмену без автоматического изменения подтверждённой брони.
- Приватный iCalendar/ICS feed для подписки из Google Calendar и других календарей.
- Шаблон ссылки на предоплату и отправка её клиенту из карточки заявки.

### Совместимость и безопасность

- Новые таблицы создаются миграционно через `CREATE TABLE IF NOT EXISTS`; существующая база v1.9.0 сохраняется.
- Старый `WEB_ADMIN_USERNAME` / `WEB_ADMIN_PASSWORD` остаётся владельцем (`owner`).
- `viewer` не может выполнять POST-изменения; системные настройки, интеграции и восстановление backup доступны только `owner`.
- Вложения ограничены 20 МБ и сохраняются под случайным внутренним именем.
- Приватный календарь защищён случайным токеном и выключен по умолчанию.

## [1.9.0] — 2026-09-20

### Добавлено

- Помесячный календарь бронирований в Web Admin с арендой, монтажом/уборкой и ручной занятостью.
- Автоматические напоминания клиенту и администраторам для подтверждённых/оплаченных заявок.

- Напоминания выключены, пока администратор явно не включит их в Web Admin.

### Совместимость

- Существующая SQLite-база мигрирует автоматически без удаления заявок и настроек.
- Telegram `/admin`, Web Admin v1.8 и конкурентная защита v1.8.2 продолжают работать.

## [1.8.2] — 2026-09-20

### Добавлено

- Per-chat очередь: события одного диалога выполняются строго последовательно.
- Глобальный лимит одновременно выполняемых Telegram updates через `MAX_CONCURRENT_UPDATES` (по умолчанию 32).

- Метрики очереди в Telegram `/admin → Статистика` и Web Admin dashboard.

### Совместимость

- Существующие активные формы автоматически получают submit-token при миграции.
- Старые заявки остаются без изменений.
- Разные клиенты по-прежнему обрабатываются параллельно; блокировка действует только внутри одного чата.
