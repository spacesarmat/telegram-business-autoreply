# v1.8.2 — конкурентная безопасность

Релиз повышает надёжность бота при одновременной работе нескольких клиентов и быстрых повторных действиях одного пользователя.

## Что изменилось

- 🔒 отдельная очередь/lock для каждого Telegram-чата;
- ⚡ разные клиенты продолжают работать параллельно;
- 🛡 повторное нажатие одной кнопки во время обработки не запускает действие второй раз;
- 🧾 каждая форма получает уникальный `submission_token`;
- 🗄 SQLite гарантирует одну заявку на один submit-token;
- 🔁 повторный submit возвращает уже созданную заявку вместо дубля;
- 🚦 глобальный лимит нагрузки `MAX_CONCURRENT_UPDATES=32`;
- 📊 текущая очередь отображается в Telegram Admin и Web Admin.

## Пример поведения

Если одновременно пишут 20 разных клиентов — их диалоги могут обрабатываться параллельно. Если один клиент за секунду отправляет несколько ответов, его события выстраиваются в очередь:

```text
Клиент A: сообщение 1 → сообщение 2 → callback
Клиент B: сообщение 1 → callback
Клиент C: сообщение 1
```

A, B и C работают параллельно, но события внутри A выполняются строго последовательно.

## Защита отправки заявки

Даже при двух параллельных попытках `Отправить заявку` UNIQUE-ограничение по `submission_token` не позволяет создать две строки в `form_submissions`.

## Настройка

По умолчанию:

```env
MAX_CONCURRENT_UPDATES=32
```

Для обычной установки менять это значение не требуется. Допустимый диапазон: 1–256.

## Обновление Docker

```bash
sudo docker pull ghcr.io/spacesarmat/tgautoreply:latest
```

После загрузки образа пересоздайте контейнер. SQLite мигрируется автоматически, старые заявки не удаляются.
