# v2.1.0 — два зала и операционная автоматизация

Большой релиз для реальной эксплуатации площадки с несколькими залами.

## Главное

- отдельные сущности **Зал 1 / Зал 2** с переименованием и отключением из Web Admin;
- выбор зала в форме «Аренда Фабрики»;
- отдельные тарифы, описание базовой цены, технические буферы, правила бронирования, регулярная и ручная занятость по каждому залу;
- 15-минутный (настраиваемый) временный **hold** слота во время подтверждения формы;
- ближайшие свободные альтернативы и лист ожидания с уведомлением после отмены брони;
- учёт оборудования/ресурсов и контроль остатка на пересекающихся мероприятиях;
- отдельный возвратный залог, ответственный менеджер и задачи по заявке;
- пакеты/шаблоны услуг с применением к стоимости заявки;
- публичная карточка заявки, QR и PDF-подтверждение;
- публичная страница `/book`, API и исходящие webhook-события;
- массовые действия, архивирование и мониторинг в Web Admin;
- Telegram Mini App через настраиваемый HTTPS URL;
- опциональный эквайринг ЮKassa: создание платежа, журнал транзакций и webhook с проверкой фактического статуса через API ЮKassa.

## Миграция

SQLite обновляется автоматически. Существующие формы и заявки сохраняются. При первом запуске создаются «Зал 1» и «Зал 2», существующие формы привязываются к обоим. Старые ручные блокировки без зала считаются глобальными и продолжают блокировать обе площадки.

## Внешние интеграции

ЮKassa, публичная бронь, Mini App и входящие webhooks требуют публичного HTTPS-адреса. Секрет ЮKassa не входит в архив и задаётся только в Web Admin. Для webhook ЮKassa используйте `/payments/yookassa/webhook`.

## Совместимость

Обновление выполняется поверх v2.0.x без удаления `/data/bot.db`. Перед обновлением рекомендуется штатный backup из Web Admin.
